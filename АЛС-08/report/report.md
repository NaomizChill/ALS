# Цель работы

Приобретение практических навыков по настройке динамического распределения IP-адресов посредством протокола DHCP (Dynamic Host Configuration Protocol) в локальной сети.

# Ход выполнения

В логической рабочей области проекта был добавлен сервер dns-irkolontirskiy и подключён к коммутатору msk-donskaya-irkolontirskiy-sw-3 через порт FastEthernet0/2. После физического подключения порт коммутатора был активирован, а для DNS-сервера была задана статическая сетевая конфигурация: IP-адрес 10.128.0.5, маска подсети 255.255.255.0, шлюз по умолчанию 10.128.0.1. Далее на сервере была настроена служба DNS, а на маршрутизаторе msk-donskaya-irkolontirskiy-gw-1 — служба DHCP для пользовательских подсетей. После этого на оконечных устройствах статическая адресация была заменена на динамическую, и выполнена проверка корректности выдачи адресов и сетевой связности между узлами разных подсетей.

## Добавление DNS-сервера в топологию

На логической схеме сети был размещён новый сервер dns-irkolontirskiy, подключённый к коммутатору msk-donskaya-irkolontirskiy-sw-3. На итоговой топологии видно, что сервер DNS был включён в серверный сегмент наряду с web-, file- и mail-серверами, что обеспечивает централизованное обслуживание запросов разрешения имён внутри сети.

## Анализ работы DHCP в режиме симуляции

В режиме симуляции в Cisco Packet Tracer был подробно рассмотрен процесс получения IP-адреса клиентским устройством по протоколу DHCP. В ходе анализа было установлено, что взаимодействие между клиентом и DHCP-сервером происходит по стандартной схеме обмена сообщениями, включающей четыре этапа: Discover, Offer, Request и Acknowledgment.

## DHCP Discover

На первом этапе клиентское устройство, не имеющее IP-адреса, формирует широковещательный запрос DHCP Discover. В данном сообщении поле Client Address имеет значение 0.0.0.0, что указывает на отсутствие назначенного IP-адреса. Запрос отправляется на широковещательный адрес с целью обнаружения доступных DHCP-серверов в сети.

![DHCP Discover: формирование запроса клиентом](10.png){ #fig:010 width=85% }

В сообщении также передаётся аппаратный адрес клиента (MAC-адрес), который используется сервером для идентификации устройства.

## DHCP Offer

После получения запроса DHCP Discover DHCP-сервер формирует ответ DHCP Offer, в котором предлагает клиенту свободный IP-адрес из доступного пула. В анализируемом случае сервер предложил адрес 10.128.4.30.

![DHCP Offer: предложение IP-адреса сервером](11.png){ #fig:011 width=85% }

В ответном сообщении также указываются дополнительные параметры:
- адрес DHCP-сервера (10.128.4.1),
- адрес DNS-сервера (10.128.0.5),
- маска подсети и другие опции.

## DHCP Request

На следующем этапе клиент отправляет сообщение DHCP Request, подтверждая принятие предложенного IP-адреса. Данное сообщение также передаётся широковещательно, что позволяет другим DHCP-серверам (если они есть) узнать, что адрес уже выбран.

![DHCP Request: подтверждение выбора адреса клиентом](12.png){ #fig:012 width=85% }

В сообщении указывается выбранный IP-адрес и MAC-адрес клиента.

## DHCP Acknowledgment (ACK)

Завершающим этапом является сообщение DHCP Acknowledgment (ACK), отправляемое сервером. В этом сообщении сервер окончательно закрепляет IP-адрес за клиентом и передаёт все необходимые сетевые параметры.

![DHCP ACK: подтверждение выдачи адреса](13.png){ #fig:013 width=85% }

В результате клиент получает:
- IP-адрес (например, 10.128.4.30),
- маску подсети,
- шлюз по умолчанию,
- адрес DNS-сервера (10.128.0.5).

# Контрольные вопросы

**1. За что отвечает протокол DHCP?**  

Протокол DHCP (Dynamic Host Configuration Protocol) предназначен для автоматической настройки сетевых параметров узлов в IP-сети. Он позволяет клиентским устройствам получать IP-адрес и другие параметры без ручной конфигурации.

Основные функции DHCP:
- автоматическая выдача IP-адресов из заданного диапазона;
- назначение маски подсети;
- указание шлюза по умолчанию;
- передача адреса DNS-сервера;
- централизованное управление адресным пространством.

Использование DHCP упрощает администрирование сети и снижает вероятность ошибок при настройке.

**2. Какие типы DHCP-сообщений передаются по сети?**  

В процессе работы DHCP используется несколько типов сообщений. Основные из них образуют последовательность взаимодействия клиента и сервера:

- **DHCP Discover** — широковещательный запрос клиента для поиска DHCP-сервера;
- **DHCP Offer** — ответ сервера с предложением IP-адреса;
- **DHCP Request** — подтверждение клиентом выбора предложенного адреса;
- **DHCP ACK (Acknowledgment)** — окончательное подтверждение и выдача параметров сервером.

Дополнительно могут использоваться:
- **DHCP NAK** — отказ в выдаче адреса;
- **DHCP Release** — освобождение адреса клиентом;
- **DHCP Inform** — запрос дополнительных параметров без получения IP.

**3. Какие параметры могут быть переданы в сообщениях DHCP?**  

DHCP-сервер может передавать клиенту различные параметры конфигурации сети:

- IP-адрес клиента;
- маска подсети;
- шлюз по умолчанию (default gateway);
- адрес DNS-сервера;
- доменное имя;
- время аренды IP-адреса (lease time);
- адрес сервера времени (NTP);
- другие дополнительные опции.

Передача этих параметров позволяет полностью автоматизировать настройку сетевого интерфейса.

**4. Что такое DNS?**  

DNS (Domain Name System) — это распределённая система доменных имён, предназначенная для преобразования символьных имён (доменов) в IP-адреса и обратно.

Основные функции DNS:
- сопоставление доменных имён и IP-адресов;
- обеспечение удобного доступа к ресурсам сети;
- поддержка иерархической структуры доменов;
- кэширование результатов запросов для ускорения работы.

DNS позволяет пользователям обращаться к ресурсам по удобным именам вместо числовых адресов.

**5. Какие типы записи описания ресурсов есть в DNS и для чего они используются?**  

В DNS используются различные типы ресурсных записей (Resource Records), каждая из которых выполняет определённую функцию:

- **A (Address Record)**  
  Сопоставляет доменное имя с IPv4-адресом.

- **AAAA**  
  Сопоставляет доменное имя с IPv6-адресом.

- **CNAME (Canonical Name)**  
  Указывает псевдоним домена на каноническое имя.

- **MX (Mail Exchange)**  
  Определяет почтовые серверы для домена.

- **NS (Name Server)**  
  Указывает серверы имён, обслуживающие домен.

- **PTR (Pointer Record)**  
  Используется для обратного разрешения (IP → имя).

- **TXT**  
  Содержит произвольную текстовую информацию (например, SPF-записи).

- **SOA (Start of Authority)**  
  Описывает основную информацию о зоне DNS.

Каждый тип записи выполняет свою роль в обеспечении корректной работы системы доменных имён.
